## Возможности

### Основные модули

| Модуль | Описание |
|--------|----------|
| **Дашборд** | Сводка активности, метрики, статистика по задачам, сделкам, контактам и онлайн-пользователям |
| **Задачи** | Создание, назначение, приоритеты, дедлайны, комментарии, подзадачи, вложения |
| **Сделки (Kanban)** | Визуальная воронка продаж с этапами, вероятностью закрытия и валютой |
| **Контакты** | Клиенты, поставщики, партнеры с тегами, заметками, импортом и слиянием |
| **Проекты** | Управление проектами с прогрессом, датами, иерархией и привязкой к задачам/сделкам |
| **Пользователи** | Управление командой, ролями, правами доступа, аватарами и онлайн-статусом |
| **Роли** | Гибкая система ролей с настраиваемыми страницами доступа |
| **Статусы** | Кастомные статусы для задач, проектов и сделок |
| **Вложения** | Загрузка файлов до 2 ГБ к задачам, сделкам, контактам, проектам и комментариям |
| **Комментарии** | Обсуждение задач с поддержкой вложений |
| **Глобальный чат** | Корпоративный чат между пользователями системы |
| **Уведомления** | Внутренние уведомления о событиях с возможностью отметить прочитанными |

| **Почта (IMAP)** | Автоматическое создание задач из входящих писем |

## Стек технологий

### Backend
- **Runtime:** Node.js 20
- **Framework:** Express 4
- **Language:** TypeScript 5.4
- **ORM:** Prisma 5.22
- **Database:** PostgreSQL 16
- **Auth:** JWT (bcryptjs + jsonwebtoken)
- **Uploads:** Multer (до 2 ГБ на файл)
- **Email:** IMAP (imapflow + mailparser)
- **Push:** Web Push API (web-push)

### Frontend
- **Framework:** React 18
- **Bundler:** Vite 5
- **Language:** TypeScript 5.4
- **Routing:** React Router DOM 6
- **HTTP Client:** Native fetch

### Инфраструктура
- **Containerization:** Docker + Docker Compose
- **Web Server:** Nginx (для фронтенда)
- **File Storage:** NFSv4 (NAS/Synology) — физическое хранение вложений
- **OS:** Ubuntu 24.04 LTS (рекомендуется)

## Быстрый старт

### Требования

- Docker 24+ и Docker Compose 2+
- Git
- NFS-сервер (для хранения вложений) — опционально, можно использовать локальную директорию

### Установка

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/jacksvits/wecrm.git
cd wecrm

# 2. Создайте директорию для загруженных файлов
mkdir -p /mnt/nfs/wecrm-uploads

# 3. (Опционально) Примонтируйте NFSv4 хранилище
# sudo mount -t nfs4 <NAS_IP>:/volume2/wecrm /mnt/nfs/wecrm-uploads

# 4. Запустите все сервисы
docker compose up --build -d

# 5. Примените миграции БД
docker compose exec backend npx prisma migrate deploy

# 6. Заполните начальные данные (опционально)
docker compose exec backend npx prisma db seed
```

### Доступ

- **CRM:** http://localhost (или IP вашего сервера)
- **API:** http://localhost:4000

### Демо-данные для входа

| Email | Пароль | Роль |
|-------|--------|------|
| `admin@wecrm.local` | `admin123` | Администратор |

## Модули

### 📊 Дашборд

Главная страница CRM с полной сводкой активности:

- **Метрики в реальном времени:**
  - Активные задачи
  - Просроченные задачи
  - Сделки в работе
  - Общая сумма сделок
  - Завершённые проекты
  - Количество пользователей
  - Пользователи онлайн

- **Список онлайн-пользователей** с аватарами
- **Воронка продаж** — распределение сделок по этапам
- **Лента активности** — последние 20 действий в системе

### 📋 Задачи

Полноценный таск-менеджер:

- **Создание задач** с заголовком, описанием, приоритетом и дедлайном
- **Статусы:** `open`, `in_progress`, `done`, `cancelled` (настраиваемые)
- **Приоритеты:** `low`, `medium`, `high`, `urgent`
- **Назначение исполнителей** — несколько пользователей на одну задачу
- **Подзадачи** — иерархическая структура (родитель → дочерние)
- **Привязка к проектам, контактам и сделкам**
- **Комментарии** с вложениями
- **Вложения** — файлы любого типа до 2 ГБ
- **Источник email** — задачи, созданные из писем
- **Фильтрация** по статусу, приоритету, исполнителю, проекту

### 💰 Сделки

Визуальная воронка продаж (Kanban-доска):

- **Этапы:** `lead` → `negotiation` → `proposal` → `won`/`lost`
- **Вероятность закрытия** для каждой сделки
- **Валюта** (по умолчанию RUB)
- **Сумма сделки** и ожидаемая дата закрытия
- **Привязка к контактам и проектам**
- **Drag & drop** между этапами

### 👤 Контакты

Управление клиентами и партнёрами:

- **Типы:** клиент, поставщик, партнёр
- **Контактные данные:** email, телефон (множественные)
- **Компания, теги, заметки**
- **Привязка к сделкам и задачам**
- **Импорт** из VCF/CSV
- **Слияние дублей**

### 🏗 Проекты

Управление проектами:

- **Название, описание, статус, прогресс**
- **Даты начала и окончания**
- **Иерархия** — родительские/дочерние проекты
- **Привязка задач и сделок**

### 👥 Пользователи и роли

Управление командой:

- **Профили** с аватаром, email, username
- **Роли:** Администратор, Менеджер, Разработчик, Пользователь
- **Настраиваемые страницы доступа** для каждой роли
- **Онлайн-статус** — heartbeat каждые 30 секунд
- **Тёмная тема** — переключение в профиле
- **Скрытие завершённых задач**

### 📎 Вложения

Загрузка файлов к любой сущности:

- **Максимальный размер:** 2 ГБ
- **Поддерживаемые типы:** любые
- **Превью изображений** в комментариях
- **Скачивание** с правильной кодировкой имени файла (RFC 5987)
- **Хранение:**
  - Обычные вложения → `/volume2/NFS/wecrm/`
  - Комментарии → `/volume2/NFS/wecrm/comments/`

### 💬 Комментарии

Обсуждение внутри задач:

- **Текстовые комментарии**
- **Вложения** — изображения с превью, файлы со ссылкой на скачивание
- **Автор** с аватаром и именем
- **Удаление** своих комментариев

### 🌐 Глобальный чат

Корпоративный чат между пользователями:

- **Отправка сообщений** в реальном времени
- **Авторы** с аватарами
- **Удаление** своих сообщений
- **Доступ** из бокового меню

### 🔔 Уведомления

Внутренняя система уведомлений:

- **Типы:** задача, комментарий, звонок, сделка, упоминание, системное
- **Заголовок, текст, ссылка**
- **Отметка прочитанными** — по одному или все сразу
- **SSE-стрим** для мгновенной доставки

## Интеграции

### 📧 Почта (IMAP)

Автоматическое создание задач из входящих писем:

- Подключение к любому IMAP-серверу (SSL/TLS или STARTTLS)
- Создание задачи из темы и тела письма
- Автоматическое создание контакта для нового отправителя
- Определение приоритета по хэштегам: `#urgent`, `#high`, `#low`
- Перемещение обработанных писем в указанную папку
- Защита от дублей по `Message-ID`
- Настройка через UI без перезапуска сервера

**Настройка:**
1. Войдите в CRM → **Настройки** → вкладка **Почта**
2. Заполните параметры IMAP
3. Сохраните → email-worker автоматически подхватит настройки

### 📞 Телефония (Novofon)

Интеграция с облачной АТС Novofon:

- **Входящие/исходящие звонки**
- **Запись разговоров** — скачивание из CRM
- **Автосоздание контакта** по номеру звонящего
- **Автосоздание задачи** при пропущенном звонке
- **История звонков** с фильтрацией
- **Сотрудники** — список из Novofon API
- **Callback** — обратный звонок из CRM

**Webhook-эндпоинты:**
- `POST /api/telephony/webhook` — события звонков
- `POST /api/telephony/iov` — запись разговора

### 🔷 VK ID

Авторизация через ВКонтакте:

- **OAuth 2.0** — стандартный flow
- **Получение данных** — имя, email, аватар
- **Автоматическая регистрация** новых пользователей

**Эндпоинты:**
- `GET /api/vk/config` — конфигурация (client_id, redirect_uri)
- `POST /api/vk/id-auth` — обмен кода на токен
- `GET /api/vk/callback` — callback URL

### 💬 MAX (мессенджер)

Интеграция с мессенджером MAX:

- **Отправка сообщений** через API
- **Webhook** для входящих сообщений
- **Привязка чата** к пользователю

### 🔔 Push-уведомления

Web Push уведомления в браузере:

- **Подписка** на уведомления
- **VAPID-ключи** для безопасной доставки
- **Уведомления** о новых задачах и активности

## Хранение файлов

Все вложения физически хранятся **вне контейнеров** — на хост-сервере или на сетевом хранилище (NAS) через NFSv4.

```
NAS / NFS-сервер
└── /volume2/wecrm/              ← физическое хранилище
    ├── comments/                ← вложения комментариев
    │   └── <uuid>.jpg
    ├── backup/                  ← резервные копии БД
    │   └── base/
    │       └── wecrm_backup_YYYYMMDD_HHMMSS.sql.gz
    └── <uuid>.jpg               ← остальные вложения

        ↑ NFSv4 (rw, vers=4.0)

Ubuntu Server
└── /mnt/nfs/wecrm-uploads/      ← точка монтирования

        ↑ Docker bind volumes

Containers:
├── backend       → /app/uploads
├── email-worker  → /app/uploads
└── frontend      → /usr/share/nginx/html/uploads (read-only)
```

### Настройка NFSv4 (пример для Synology NAS)

```bash
# 1. Установите клиент NFS
sudo apt-get install -y nfs-common

# 2. Создайте точку монтирования
sudo mkdir -p /mnt/nfs/wecrm-uploads

# 3. Примонтируйте NFSv4
sudo mount -t nfs4 <NAS_IP>:/volume2/NFS/wecrm /mnt/nfs/wecrm-uploads

# 4. Добавьте в /etc/fstab для автомонтирования
echo "<NAS_IP>:/volume2/NFS/wecrm /mnt/nfs/wecrm-uploads nfs4 defaults,_netdev 0 0" | sudo tee -a /etc/fstab

# 5. Установите права для Docker
sudo chmod -R 777 /mnt/nfs/wecrm-uploads
```

### Локальное хранение (без NAS)

```bash
mkdir -p /mnt/nfs/wecrm-uploads
chmod -R 777 /mnt/nfs/wecrm-uploads
```

## Резервное копирование

Автоматическое ежедневное резервное копирование базы данных.

### Расписание

- **Частота:** каждый день в 01:00
- **Хранение:** 7 последних копий (старше — автоматически удаляются)
- **Расположение:** `/volume2/NFS/wecrm/backup/base/`
- **Формат:** `wecrm_backup_YYYYMMDD_HHMMSS.sql.gz`

### Crontab

```bash
0 1 * * * /home/crm/wecrm/backup.sh >> /home/crm/wecrm/backup.log 2>&1
```

### Ручной запуск

```bash
/home/crm/wecrm/backup.sh
```

### Восстановление из бэкапа

```bash
# Распаковать
gunzip /mnt/nfs/wecrm-uploads/backup/base/wecrm_backup_20260828_010000.sql.gz

# Восстановить
docker exec -i wecrm-db-1 psql -U crm -d wecrm < /mnt/nfs/wecrm-uploads/backup/base/wecrm_backup_20260828_010000.sql
```

## Команды

```bash
# Запуск
docker compose up -d

# Пересборка
docker compose up --build -d

# Логи
docker compose logs -f backend
docker compose logs -f frontend
docker compose logs -f email-worker

# Миграции БД
docker compose exec backend npx prisma migrate deploy
docker compose exec backend npx prisma generate

# Сидинг (демо-данные)
docker compose exec backend npx prisma db seed

# Резервное копирование
/home/crm/wecrm/backup.sh

# Остановка
docker compose down

# Полный сброс (удалит данные!)
docker compose down -v
docker system prune -f
```
